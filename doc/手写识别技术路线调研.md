## 2. RQ1：主流输入法怎么做

### 2.1 行业通行架构（证据中等）

| 引擎 | 输入形态 | 技术栈 | 证据 |
|---|---|---|---|
| MyScript（多家手写笔/PDA/eNote 的底层引擎） | 数字墨水（笔轨迹） | 官方自述："neural networks""trained on millions of writing samples across 70+ languages""20+ years of R&D" | 官网 `/sdk/`、`/handwriting-recognition` 页面正文（已抓取） |
| Google ML Kit **Digital Ink Recognition** | 数字墨水 | 官方定位：接收笔迹（不是图片），支持"数百种语言"，**端侧运行**，模型按语言包下载 | 官方文档与官方博客标题+摘要（正文未能抓取，细节未一手核实） |
| 搜狗 / 讯飞 / 百度输入法 | 笔迹（手指轨迹） | 无公开技术白皮书；从检索到的材料只能确认"手写输入"是功能之一 | 未获一手技术材料 |
| 专利线索 | 笔迹 | 例如 CN101853126A《一种联机手写句子实时识别方法》：笔划采集 → 实时识别模块 → 对提笔后的整句轨迹识别 | Google Patents 检索结果 |

**综合判断（证据：中）**：主流输入法普遍是 **在线（ink/轨迹）识别**，端侧小模型 +（可选）云端大模型 + 语言模型纠错；而不是"把手写当成图片"。这一点与 RQ2/RQ3 的技术线一致：**轨迹信息比光栅图像更有价值**，且更省算力（不用做图像归一化/去噪）。

### 2.2 公开的精度量级

- 单个汉字（3755 类）离线 CNN 上限：**97.3%**（ICDAR2013 离线竞赛库，9 层 CNN 基线）；压缩版 **2.3 MB / 97.09% / 单线程 CPU 9.7 ms/字**；另一路线（DirectMap+ConvNet）**96.95% / 23.5 MB / 297 ms**（arXiv 1702.07975 表格，已抓取）。
- 商业输入法对"规整手写"的宣传精度通常 ≥95%，但**无一手可比数据**，本报告不引用。

## 3. RQ2：PDA / 资源受限时代怎么做

### 3.1 两条完全不同的技术线

1. **拉丁字母：单笔画字母表**（Palm Graffiti 一类）。每个字母一笔写完、形状互相远离，用模板匹配即可，代价极低但只适用 26 个字母（背景知识，未引用文献）——**对汉字不适用**（汉字平均 8 笔、3755+ 类）。
2. **汉字：联机轨迹特征 + 二次判别分类器**。这是 1990s–2010s 的实际主流，也是本平台最值得借鉴的一条：**不需要反向传播、不需要卷积，只需要"好特征 + 一个线性/二次分类器"**。

### 3.2 这条线的权威数字（一手，论文摘要）

CASIA/NLPR 官方基准（Liu, Yin, Wang, Wang, *Online and Offline Handwritten Chinese Character Recognition: Benchmarking on New Databases*, Pattern Recognition 46(1):155–162, 2013）在 3755 类（GB2312 一级字）上的结论：

| 方法 | 离线 HWDB1.1 | 在线 OLHWDB1.1 |
|---|---|---|
| MQDF（仅用 DB1.1 训练） | **89.55%** | **93.22%** |
| MQDF（DB1.0+DB1.1 训练） | 90.71% | 93.95% |
| DFE + DLQDF（判别式学习） | **92.08%** | **94.85%** |

要点：
- **在线比离线高 3.7 个点**（同样的分类器族、同样的 3755 类）。轨迹里的"笔顺/方向"信息是免费的额外信号。
- 特征就是 **512 维**：8 方向梯度直方图 + **伪二维（pseudo-2D）归一化**（离线用 NCGF；在线用轨迹方向 + 伪二维双矩归一化）。
- 分类器 MQDF（Kimura 1987 的 Modified Quadratic Discriminant Function）本质是"每类一个均值 + 低秩协方差"的二次判别；**核心开销是 K×D 级别**，在 2000 年代的掌上设备上完全跑得动。

### 3.3 结构匹配路线（另一支，很轻）

- `HanziLookupJS`（GitHub `gugray/HanziLookupJS`，181★；Rust 版 `gugray/hanzi_lookup` 103★）：**按笔顺做笔画序列/形状匹配**，匹配器只有 **12 KB JS**、数据 `mmah.json` 仅 **827 KB**（数据来自 Make Me a Hanzi），浏览器里就能跑，返回 n-best。
- 特点：零训练、体积极小；**依赖书写笔顺基本正确、字形规整**；对连笔/潦草退让明显。无公开精度数字。
- 适合做"第二意见"或与统计识别融合出候选集。

## 5. 我在本机的实测（**本报告最硬的一块证据**）

目的：把"论文数字"换成"我们平台上能拿到什么"。做法是下载 CASIA 官方 **512 维在线特征**（OLHWDB1.1，3755 类，240/60 书写人划分），在同一测试集上比较不同分类器与维度。推理成本按 K×D 乘加计（K=类数，D=维数）。

### 5.1 分类器对比（3755 类 / 训练集 89.9 万样本）

| 分类器 | top-1 | top-5 | 训练成本 | 推理乘加 |
|---|---|---|---|---|
| **最近类均值 NCM（欧氏）** | **81.53%** | **93.62%** | 只算类均值（秒级） | K×D |
| 对角协方差高斯（MQDF 退化版） | 76.76% | 91.76% | 类均值+方差 | 2×K×D |
| 线性 softmax（15 万样本，Adam 8 epoch） | 74.31% | 90.97% | 数分钟 | K×D |
| 白化 + NCM（LDA 式）D=512 | 77.56% | 90.79% | 协方差+特征分解 | K×D + D² |
| 文献 MQDF（PR2013） | 93.22% | — | 全协方差 + 特征分解 + 判别学习 | ~K×(D+M·D) |

**结论 1：分类器不是瓶颈，特征才是。** 一个"傻子分类器"（类均值）就拿到 81.5%，比线性 softmax 还高（3755 类 × 40 样本/类时线性严重过拟合）；文献 MQDF 的 93% 主要是"全协方差 + 判别式学习"的红利。

### 5.2 只保留最常用 1000 类（测试集里该类样本 59,807 个）

| 分类器 | top-1 | top-5 |
|---|---|---|
| **NCM** | **84.90%** | **95.70%** |
| 对角协方差高斯 | 80.47% | 94.21% |
| 线性 softmax（512 维） | 80.18% | 94.25% |
| 线性 softmax（随机投影 128 维） | 72.83% | 90.79% |

**结论 2：把类数从 3755 收到 1000，只换来 3.4 个点**（81.5→84.9）。也就是说"类数"不是主要矛盾，**特征质量与数据真实性**才是；但同时 1000 类的推理成本只有 3755 类的 27%。

### 5.2b 同一分类器下：**在线 vs 离线**（同一套官方特征、同一个 NCM）

我又下载了离线侧 **HWDB1.1 官方 NCGF-512 特征**（89.8 万/22.4 万样本、3755 类）复现同一实验：

| 特征 | 分类器 | 3755 类 top-1 / top-5 | 1000 类 top-1 / top-5 |
|---|---|---|---|
| **在线**（OLHWDB1.1，轨迹方向 512 维） | NCM | **81.53% / 93.62%** | **84.90% / 95.70%** |
| 离线（HWDB1.1，NCGF 512 维） | NCM | 72.84% / 88.81% | 77.92% / 92.39% |
| 在线 | 对角协方差高斯 | 76.76% / 91.76% | 80.47% / 94.21% |
| 离线 | 对角协方差高斯 | 73.87% / 89.41% | 78.84% / 92.86% |

**结论 2b：在同等特征质量、同等分类器下，"用轨迹"比"用图像"高 8.7 个点**（81.5% vs 72.8%，3755 类）。
这比文献里 MQDF 的在线/离线差（3.7 点）更大，说明**在线信号对我们的价值比历史上更突出**——
我们反正拿得到轨迹，没有任何理由走图像路线。

### 5.3 维度 vs 精度（决定计算预算，NCM + PCA 截断）

| 维度 r | 3755 类 top-1/top-5 | 1000 类 top-1/top-5 |
|---|---|---|
| 512 | 81.53% / 93.62% | 84.90% / 95.70% |
| 256 | 81.37% / 93.56% | 84.78% / 95.68% |
| 128 | 80.10% / 93.04% | **84.01% / 95.40%** |

**结论 3：降到 128 维几乎不掉点**（-0.9 点）。1000 类 × 128 维 = **12.8 万乘加 ≈ 150 ms（WASM）**，比现在（25.6 万乘加 / 300 ms）**更快**，精度高 24 个点。

### 5.4 反面证据：我自己写的"朴素在线特征"不行

我按"最直觉"的方式写了在线特征（等弧长重采样 + 包围盒归一化 + 8 方向按段长加权的 3×3/4×4/5×5 网格直方图 + 抬笔方向 + 落点密度，89/152/233 维），在 40/20 书写人划分上跑 NCM：

- 3755+171 类：**top-1 仅 4%**；跨两位书写人（3742 类）时**正确类的排名中位数 ≈ 975/3742**。

而同一批数据上，官方 512 维特征 + 同一个 NCM 是 81.5%。

**结论 4（关键工程量判断）**：那 512 维不是"随便切个直方图"，它包含 **伪二维归一化**（按线密度投影分别规整 x/y 方向的笔画分布）与 8 方向梯度分解。**特征工程是本路线的主要工作量与主要风险**：抄对归一化级联 ≈ 80%+；抄错/简化 ≈ 个位数到几十个点。

## 6. 计算预算换算（灵机 VM）

方案按"PCA 投影（512→r，512×r）+ 分类器（K×r）"两段计（**投影也是乘加，不能省**）：

| 方案 | 乘加数 | 预估 WASM 耗时 | 精度预期 |
|---|---|---|---|
| 现状（1000 类 × 256 维离线光栅特征 + 线性，字体合成数据） | 256k | 300 ms（实测） | 实测：手指仿真 top-1 60%、top-8 80% |
| 1000 类 × **512 维** + NCM（不降维） | 512k | ~610 ms | 84.9%（实测） |
| PCA-256（131k）+ 1000 类 × 256（256k）= 387k | 387k | ~460 ms | 84.8%（实测） |
| **PCA-128（66k）+ 1000 类 × 128（128k）= 194k** | 194k | **~230 ms** | **84.0%（实测）** |
| PCA-64（33k）+ 1000 类 × 64（64k）= 97k | 97k | ~120 ms | 未测（估计 80~83%） |
| PCA-128 + 3755 类 × 128 = 66k + 480k | 546k | ~650 ms | 80.1%（实测） |
| PCA-128 + 两阶段剪枝（粗 64 簇 + 细 ~120 类，均 128 维） | 66k + 23k = 89k | ~110 ms | 取决于粗分类器召回（需实测） |
| 3755 类 + MQDF（M=8 主分量） | ~17M | ~20 s | 93.2%（文献）→ **不可行** |
| 9 层 CNN（文献压缩版） | 数千万 | 数分钟 | 97.09%（文献）→ **不可行** |

> 注：WASM 与原生之比按现版 300 ms / 67 ms（≈4.5×）折算；乘加成本已计入"热循环用 lambda 局部量"这一前提（见 `doc/AGENTS.md` 2026-11-01 条目）。

**特征提取开销**：在线特征只处理 30~150 个轨迹点 → 数千次运算（≈1 ms 级）；离线光栅特征要处理 1024 个像素（现版 ≈4 ms）。在线路线在特征端也更便宜。

## 7. 路线候选与决策矩阵

> 下表的"精度预期"分两档：**有实测/文献支撑的**，和**需要先做可行性验证的**。我不想给你一个凭感觉的数字。

### 路线 A｜只换数据：保留现有光栅特征与线性分类器，用 CASIA-HWDB1.1 真迹重训

| 项 | 内容 |
|---|---|
| 精度预期 | **已实测上限**：离线官方 NCGF-512 + NCM = 72.8%（3755 类）/ 77.9%（1000 类）；文献同特征族 + MQDF = 89.55%。我们现有特征明显弱于 NCGF（无伪二维归一化、仅 4 方向）→ **预计 62~72%**，需实测 |
| 推理成本 | 不变（1000×256 = 256k MAC，300 ms） |
| 工程量 | **小**：只需写图像特征管线（我已有光栅特征代码）+ 训练 + 导出（导出链路已存在） |
| 风险 | 低。精度提升幅度受限（特征天花板） |
| 许可 | CASIA 学术用途；权重分发属灰区 |

### 路线 B｜（推荐）在线轨迹特征 + 最近类均值 / 线性，1000~3755 类

| 项 | 内容 |
|---|---|
| 精度预期 | **1000 类 84~85%（top-5 95%+）、3755 类 80~82%**——这是我在官方 512 维在线特征上**实测**的 NCM 数字；只要我们自己的特征能做到接近 NCGF，就能拿到这个量级 |
| 推理成本 | PCA-128 + 1000 类 = **194k MAC ≈ 230 ms**（比现在更快且高 24 点）；PCA-128 + 3755 类 = 546k ≈ 650 ms（加两阶段剪枝可压到 ~110 ms） |
| 训练成本 | NCM 只需类均值（分钟级）；线性/NCM 都能直接 int8 逐类量化（现有导出链路完全复用） |
| 工程量 | **中高**：需实现"伪二维归一化 + 8 方向梯度/轨迹方向"特征，并与训练侧逐位一致（我有成熟的"dump 特征逐位比对"流程可用） |
| 风险 | **特征实现正确性**是本路线唯一实质风险（见 5.4 的反面证据）；缓解办法：先用官方 512 维特征训练，再把自研特征对齐到"同一测试集 ≥80%"再落地 |
| 可选升级 | ① MQDF（全协方差低秩）+3~8 点，成本 ×2~8（3755 类不可行，1000 类需 256k~1M MAC）；② 用 CNN 教师做知识蒸馏再提 2~4 点（只影响训练端） |

### 路线 C｜极小 CNN 前向推理（1~2 层卷积 + 池化 + 线性）

| 项 | 内容 |
|---|---|
| 精度预期 | **不确定**。文献里 97% 需要 9 层/数千万乘加；在 ≤1M 乘加的预算内，最多是"一层 3×3 卷积（4~8 通道，stride 2）+ 全局池化 + 线性"，乐观估计 85~90%，也可能不如路线 B |
| 推理成本 | 1 层 8 通道 32×32 stride2：≈ 1024×9×8 = 74k MAC，可承受 |
| 工程量 | **高**：卷积要在 Scheme 里跑（现有 Gfx 层没有卷积原语），且要解决"训练/推理逐位一致"之外的权重布局与量化 |
| 风险 | 高（收益不确定 + 工程量最大） |

### 路线 D｜结构匹配（HanziLookup 式，零训练）

| 项 | 内容 |
|---|---|
| 精度预期 | 无公开数字；依赖笔顺正确。作为"候选补全"很划算 |
| 成本 | 827 KB 数据 + 12 KB 级代码；匹配开销小 |
| 工程量 | 中（数据转换 + 匹配算法 + 与统计识别融合排序） |
| 许可 | Make Me a Hanzi 派生数据（Arphic Public License），可随仓库分发 |

### 路线 E｜工程打磨（不解决精度）

两阶段剪枝、识别拆帧、候选区渐进刷新、加"整句语言模型纠错"。**建议单独排期，与 A/B/C/D 解耦。**

### 决策矩阵

## 8. 我的建议（请你选择）

**建议走 B，并按下面三步落地（每步都有可验证的交付）**：

1. **可行性验证（先做，约半天）**：在 numpy 里实现"伪二维归一化 + 8 方向特征"，在 OLHWDB1.1 上量 NCM 准确率。**判据：1000 类 top-1 ≥ 80%** 才继续；否则改用 CASIA 官方 512 维特征做训练、只把自研特征当"降级方案"，或退回 A。
2. **落地（1~2 天）**：把特征提取搬到 Scheme，与 numpy 逐位比对（我现成的 dump/比对流程）；训练 1000 类 NCM + int8 量化，走现有 `(Fs.read)` 数据文件通路；保留 3755 类作为可选档（加两阶段剪枝）。

2. **类数要多少**：1000 类（150 ms，84%）还是 3755 类（570 ms 或加剪枝 ~30 ms，80~82%）？——顺带一个反向问题：3755 类下用两阶段剪枝把耗时压回 30 ms 还有额外工程量，你要不要？

## 9. 后记（路线 B 实施结果，2026-11-01 晚）

按你的选择（B 路线 / 3755 类 / 真迹训练）已实现：`infer/app/hwr2.scm`，
与 v1（`hwr.scm`）并存、未改动 v1。**实测精度低于本报告第 7 节的预期**，如实记录：

| 配置（3755 类，CASIA 测试书写人 60 人，App 输入仿真） | top-1 | top-5 |
|---|---|---|
| 自研 512 维在线特征 + NCM | 57.4% | 77.8% |
| PCA-256 + 对角白化 + NCM | 60.6% | 80.4% |
| **PCA-128 + 对角白化 + NCM（采用）** | **58.5%** | **79.1%** |
| 官方 512 维在线特征 + NCM（参照） | 81.5% | 93.6% |

差距的根因已经定位：**CASIA 的 512 维是"伪二维双矩归一化 + 8 方向"的专有实现**，
我用"线密度投影等化映射"近似（alpha 扫描 0.4/0.55/0.7/0.85 → 0.7 最优），
即使做了 nib 层（网格分辨率 ng=48/64/96、分块 8/12、软/硬方向分配、空间双线性、
8 方向 vs 4 方向、抬笔方向特征、笔宽、模糊）等十余组消融，也只能到 57~60%。
反面证据见 §5.4（同一数据上官方特征 80.5%）。

性能：WASM 实测约 700 ms/次（原生 220 ms）。数据许可：见 AGENTS.md 2026-11-01（四）§7。

若要把这 23 个点补回来，下一步建议（按性价比）：
1. **把归一化做对**：实现 CASIA 论文里的伪二维双矩（P2DBMN）而不是等化近似；
2. **MQDF 低秩项**（+3~8 点，成本 ×2~8，3755 类不可行、1000 类可行）；
3. **小型 CNN + 知识蒸馏**（上限最高，工程量最大，见 §7 路线 C）；
4. 若可放宽"纯字体合成数据"限制，也可把 v1 的合成字体数据与本真迹数据混训，
   兼顾"理想折线输入"的鲁棒性（实测真迹模型对理想折线只对 2/20）。

## 10. 归一化专项复检（2026-11-01 深夜，"把归一化作对"）

针对"精度差距是否出在归一化"做了系统复检。**结论：不是。** 现有实现
（线密度投影等化映射，与恒等映射 α=0.7 混合，图像重采样）在所有试过的方案里最好。

评测口径统一：CASIA-OLHWDB1.1 原始笔迹，60 个书写人训练 / 60 个测试，3755 类，
最近类均值（NCM），特征 512 维（8 方向 × 8×8）。基线 = 58.3%（与线上模型 58.5% 一致）。

| 归一化方案 | top-1 | top-5 |
|---|---|---|
| **线密度等化 α=0.7（当前实现）** | **58.3%** | **78.8%** |
| 等化 α=0.55 | 54.9% | 75.6% |
| 等化 α=0.85 | 55.2% | 76.7% |
| 等比缩放（保长宽比、居中）而非拉伸填满 | 54.4% | 75.4% |
| **迭代式伪二维**（每轮用另一轴已校正的图像，2 轮） | 39.1% | 60.9% |
| 迭代式（3 轮） | 10.8% | 23.6% |
| **双矩 / Casey–Nagy 三次多项式矩拟合**（α=1.0 / 0.7） | 21.2% / 36.6% | 37.6% / 58.0% |
| 迭代矩归一化（α=1.0） | 37.1% | 58.0% |
| 正态目标 Φ⁻¹(C(x))（只规整前两阶矩的另一种写法） | 16.0% | 32.1% |
| 轨迹扭曲 + 等弧长重采样（不重采样则掉到 17.3%） | 17.3% | 33.0% |
| **NCGF 式梯度雅可比校正**（梯度 × 映射导数 / ÷ 映射导数） | 52.1% / 55.9% | — |
| 「方向取原始轨迹 + 位置用归一化坐标」（按 CASIA 描述的另一种读法） | 26.4% | 46.2% |
| 经典方向线元（DDF，2×2 线元计数 4/8 方向） | 21.7% | 40.7% |

**两条决定性的诊断**（对齐了 29,928 个样本，同一书写人同一字）：

- 用岭回归把"我的 512 维"映到"CASIA 官方 512 维"，**R² = 0.133**；反向 **R² = 0.083**。
  即两者是**近乎不相干的表示**，不是"同一特征换了个尺度/旋转"——所以调分类器、调归一化
  参数都补不回那 23 个点。
- 分类器一侧已排除：官方特征上 NCM 就是最优（81.5% > 线性 74.3% > 对角高斯 76.8%）。

**因此差距在"方向算子 + 聚合方式"的具体实现**，而不是归一化。CASIA 的 NCGF/P2DBMN
公式只在付费论文里（Liu & Sako, *Pseudo two-dimensional shape normalization methods*,
Pattern Recognition 2005），我拿不到精确式子；靠"猜实现"（上表 12 种）无法收敛到同一空间。

### 若要继续提升精度，建议按性价比选

1. **卷积特征（小 CNN + 全局池化到 ~128 维）+ NCM/线性**：唯一能稳定跨过 80% 的路子。
   本平台可承受 1 层 3×3 卷积（4~8 通道，stride 2）+ 池化 + 线性（约 20 万乘加/次），
   训练用 numpy 从零写（无 torch），可配合"教师-学生"蒸馏。工序最大，但收益确定。
2. **MQDF 低秩项**（在现有特征上 +3~8 点，成本 ×2~8）：3755 类跑不动；收到 1000 类可行
   （约 1M 乘加/次 ≈ 1.2 s）。
3. **收到 1000 类**：+3.4 点、耗时降到 27%。
4. 维持现状，把精力放到体验侧（两阶段剪枝把 700 ms 压到 ~150 ms、候选排序、整句纠错）。
